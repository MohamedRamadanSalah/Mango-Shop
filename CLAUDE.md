# POV: mango juice shop QR menu (Google Stitch)

Load the global `stitch-pro` skill before any Stitch work here and follow it.

## Decisions (made with the user, 2026-10-22)

- **Brand:** POV (Arabic بوف), a fresh mango-first juice shop in Cairo. Tagline "Your Choice. Your Point Of View." / "اختيارك ... وجهة نظرك". Brand assets: `assets/src/` (logo, packaging, cups).
- **Deliverable:** a **QR phone menu** (390px MOBILE for A/B; C is responsive phone + web; view-only: no cart, no tab bar). Screens: 01 Menu, 02 Drink detail.
- **Style:** "Mango Pop". Light, playful, bold. Shared style block: `.stitch/prompts/menu-style.md` (append it to every generate prompt). Colors: purple #7243AB, mango yellow #F9CD18, orange #F7941D, teal #17AE9D, coral #F2654A, ink #2A1640, cream canvas #FFF8E7. The logo's rounded diamond "cubes" are the motif. Sticker price tags. Never dark.
- **Language:** English + Arabic for every drink and category. Arabic names are fixed in the style block; never let Stitch invent Arabic. Font: Readex Pro (Latin + Arabic).
- **Icons:** MingCute (`icons/icon-kit.json`, `activeSet`). Never ship Material icons.

## Pipeline (per screen)

Screens are hand-built, never generated by Stitch AI (the user rejected its designs).

The client chooses between two design options (2026-10-22), each in its own folder: **A "Mango Pop"** (`tools/screens/a/`, done) and **B "Viewfinder"** (`tools/screens/b/`, own `theme.mjs` kit; spec `.stitch/prompts/design-b.md`: white canvas, viewfinder corner brackets on photos, sticky category rail, swipe carousel, grid + list rows, "say this at the counter" card; Readex Pro only). The first B ("Fresh Market Editorial") was rejected and removed on 2026-10-22. On 2026-10-27 the client asked for a third option **C "Color Blocks"** (`tools/screens/c/`, own `theme.mjs`; spec `.stitch/prompts/design-c.md`) with three rules: works on web **and** mobile (C is responsive, not 390px-only: 2/3/5 card columns, desktop checked at 1440px), the logo colours must show strongly (each category is a full-width block in its logo colour), and a very simple structure with no noise (no confetti, brackets or rotation). `compare/index.html` shows all three phones plus C in a desktop browser frame. Previews: `.stitch/previews/c/` has phone shots and `*-desktop.png` full-page shots. Previews go to `.stitch/previews/<design>/`.

1. Each screen is `tools/screens/<design>/NN-name.mjs` (exports `file`, `title`, `css`, `body`, optional `fonts`, `colors`, `baseCss`), using the menu data and helpers in `tools/screens/shared.mjs`. Photos come from `.stitch/menu-photos.json` (drink id → `assets/photos/<id>.jpg`, self-hosted; `photo()` emits `../../assets/photos/...`). Never link Stitch `lh3.googleusercontent.com/aida` URLs: they expire with 403 (9 of 16 broke on the Vercel deploy, 2026-10-24). Site is deployed on Vercel.
2. `node tools/build-screens.mjs [design]` writes `screens/<design>/NN-name.material.html` (icons as Material names from `icons/icon-kit.json`).
3. `node tools/stitch-icons.mjs apply screens/NN-name.material.html screens/NN-name.html`.
4. Verify in Chrome at `390x844x2,mobile,touch`: Readex Pro loaded on Arabic text, RTL correct, no horizontal overflow, 0 `.material-symbols-outlined`, no text in photos. Viewport screenshot to `.stitch/previews/NN-name.png`.
5. Upload once: `node tools/stitch-icons.mjs upload screens/NN-name.html <mainId> --title "NN · Name" --preview .stitch/previews/NN-name.png`.
